# Gemini 3.7 Flash 명시적 캐시 측정 보고서

## 결론

Android phone `COMPANION`의 명시적 캐시 최초 생성 기준 `MINIMUM_CACHE_TOKENS = 4,600`을 유지한다.
측정 구간에서 캐시 생성 59회가 모두 성공했고 캐시 적중률도 높았다. 측정 당시 공식 최소치로 기록된
4,096토큰과 로컬 안전선 4,600토큰 사이의 관측은 17건뿐이며, 로컬 추정치가 서버 보고 입력보다
집계상 크게 잡혔기 때문에 기준을 낮출 근거보다 생성 실패 위험을 피할 근거가 더 강하다.

이 보고서는 캐시 정책을 변경하지 않는다. Luna, 멘토, 태블릿, macOS, 프롬프트, 대화 압축도 범위 밖이다.

## 4,600 기준 판단

접두사 추정 토큰 구간별 관측은 다음과 같다.

| 추정 접두사 토큰 | 관측 |
| --- | ---: |
| 0~4,095 | 73 |
| 4,096~4,599 | 17 |
| 4,600~8,191 | 65 |
| 8,192~16,383 | 242 |
| 16,384 이상 | 55 |

4,600을 4,096으로 낮춰 새로 검토할 수 있는 최대 범위는 17건이다. 하지만 집계상 로컬 추정기가
서버 보고 입력보다 크게 잡혔으므로, 이 17건이 실제 캐시 최소치도 만족했다고 볼 수 없다. 반면
4,600 이상에서 실행한 59회는 모두 생성에 성공했다. 현재 자료는 4,600 안전선의 안정성은
지지하지만, 더 낮은 값의 비용 우위를 입증하지는 않는다.

캐시 판단에서는 `TAIL_TOO_SMALL`이 289건으로 가장 많았고, `BELOW_MINIMUM` 90건,
`NOT_BURST` 14건이었다. 최초 생성 기준보다 갱신 꼬리 기준이 더 자주 작동했지만, 이번 요청은
정책 연구가 아니라 현행 기준 유지 여부 확인이므로 갱신 상수도 변경하지 않는다.

## 한계

- JSON은 개인정보 보호를 위해 요청별 사건 대신 합계와 구간만 보존한다.
- 4,096~4,599 구간의 각 요청이 이후 몇 번 재사용됐을지는 연결할 수 없다.
- 로컬 추정치와 서버 실제 토큰의 요청별 오차 분포도 없다.
- 측정 회차의 요청 장부와 현재 남아 있는 채팅 메시지는 삭제·재시도 등의 영향으로 일대일 대응하지 않을 수 있다.
- 이 보고서는 측정 당시 정책 스냅샷을 평가하며, Google의 향후 가격·최소 토큰 정책 변경을 검증하지 않는다.

따라서 이 자료로 세밀한 최적점을 새로 계산하는 것은 적절하지 않지만, 이미 안정적으로 작동한
4,600을 유지하기에는 충분하다.
