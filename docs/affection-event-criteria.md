# 가가오독 호감도 변화 이벤트 기준

> 기준 버전: Android phone `1.7-phone`
> 작성일: 2026-08-24
> 적용 범위: Android 폰 앱의 **개인 챗봇방, 단톡방 및 각 세계선**

## 1. 결론

현재 구현은 개인 챗봇방에서 선택한 Gemini 모델(3.7 Flash 또는 3.5 Flash-Lite)이 관계상 의미 있는 사건인지 판단하고, 앱이 변화량을 엄격하게 제한하는 방식이다. 단톡방은 계속 Gemini 3.7 Flash만 사용한다.

실제 판정 기준은 다음 한 문장으로 요약된다.

> Gemini가 정상 완료된 응답에 유효한 숨은 표식을 출력하면, 개인방은 기본 호감도에, 단톡방은 해당 참여자의 요청 세계선 하트에 `-3..+2` 범위로 적용한다.

따라서 현재 호감도 변화는 다음 두 층으로 나뉜다.

1. **감정적 판단:** 요청을 처리한 Gemini 모델의 재량
2. **기술적 적용:** 앱의 결정적 파서, 턴당 `-3..+2` 제한과 저장값 `0..100` 제한

앱은 친절, 갈등, 질투, 화해 같은 사건을 직접 분류하지 않는다. 대신 모델에게 상승·하락 기준과 한 턴 범위를 주고, 최종 숫자는 앱이 다시 제한한다.

## 2. 이벤트 발생 흐름

1. 사용자가 단톡방의 활성 세계선에서 메시지를 보낸다.
2. 앱은 단톡방 참여자들의 페르소나를 합쳐 Gemini 3.7 Flash에 한 번 요청한다.
3. 모델은 대사 화자 표식과 선택적인 하트 표식을 포함한 원문을 생성한다.
4. 앱은 화자·하트 표식을 화면에서 제거하고 말풍선과 나레이션만 보여준다.
5. 모델 응답이 **정상적으로 끝나면** 원문 전체에서 하트 표식을 찾는다.
6. 참여자별 변화량을 합산해 요청을 시작한 세계선에 적용한다.
7. 최종 하트값은 `0..100`을 벗어나지 않도록 제한한다.

## 3. 모델에게 주는 현재 지시

단톡방 시스템 프롬프트에는 다음 형식 규약만 존재한다.

```text
선택적으로 [[heart:<ROOM_UUID>:+N|-N]]를 대사 문단 안에 둔다.
목록에 있는 참여자 UUID만 사용한다.
표식은 설명할 텍스트가 아닌 전송 메타데이터다.
```

여기서 중요한 점은 다음과 같다.

- 하트 표식은 **선택 사항**이다.
- `N`은 한 턴 최종값 기준 상승 `+1..+2`, 하락 `-1..-3`으로 제한된다.
- 일상적 인사·칭찬·호의는 기본 0이다. 신뢰 형성이나 관계 전환점만 상승시키고, 무례·약속 위반·거짓말·배신·반복적인 경계 침해는 더 적극적으로 하락시킨다.
- 성적 수위만으로 호감도를 올리거나 내리지 않으며, 관계 메타데이터가 대사나 상황극을 검열·순화하지 않도록 분리한다.
- 캐릭터별 민감도나 관계 단계별 가중치가 없다.
- 한 응답에서 여러 캐릭터의 하트를 동시에 바꿀 수 있다.

## 4. 유효한 변화 표식

형식은 아래와 같다.

```text
[[heart:ROOM_UUID:+N]]
[[heart:ROOM_UUID:-N]]
```

예시:

```text
[[heart:22222222-2222-2222-2222-222222222222:+2]]
[[heart:11111111-1111-1111-1111-111111111111:-1]]
```

유효 조건:

- UUID가 정확히 36자 UUID 형식이어야 한다.
- 해당 UUID가 현재 단톡방 참여자여야 한다.
- 변화량 앞에 `+` 또는 `-` 부호가 반드시 있어야 한다.
- 변화량이 Kotlin `Int`로 해석 가능한 정수여야 한다.

조건을 만족하지 않는 표식은 무시된다.

## 5. 변화량 합산과 범위 제한

같은 응답에 같은 참여자의 표식이 여러 번 나오면 모두 합산한다.

예시:

```text
[[heart:A:+2]][[heart:A:-3]][[heart:B:+3]]
```

적용 결과:

- A: `-1`
- B: `+2` (상승 상한 적용)

합산된 변화량은 기존 하트값에 더해지고 결과는 `0..100`으로 제한된다.

| 기존 값 | 변화량 | 저장 값 |
|---:|---:|---:|
| 50 | +2 | 52 |
| 99 | +5 | 100 |
| 1 | -4 | 0 |
| 0 | -1 | 0 |

## 6. 변화가 적용되지 않는 경우

다음 경우에는 호감도가 변하지 않는다.

- 모델이 하트 표식을 출력하지 않은 경우
- 존재하지 않거나 다른 방의 UUID를 사용한 경우
- 표식 문법이나 숫자 형식이 잘못된 경우
- 사용자가 응답 생성을 중간에 취소한 경우
- 말풍선 일부가 표시됐지만 스트림이 오류로 끝난 경우
- 앱이 모델 응답을 받기 전에 요청 자체가 실패한 경우

현재 하트 파싱은 정상 완료된 단톡방 응답 원문에만 실행된다. 중간 취소·부분 실패 때는 화면에 나온 대사를 보존할 수 있지만 하트 변화는 적용하지 않는다.

## 7. 세계선 적용 규칙

- 하트는 단톡방 전체에 하나만 있는 값이 아니다.
- 각 세계선은 참여자별 하트 목록을 별도로 가진다.
- 변화는 요청을 시작한 세계선에만 적용된다.
- 다른 세계선의 값은 바뀌지 않는다.
- 분기할 때 현재 세계선의 대화와 하트값을 그대로 복사한다.
- 분기 이후의 대화와 하트 변화는 서로 독립적이다.
- 모델 응답이 진행 중일 때는 분기할 수 없게 잠겨 있어 대화 복사 시점과 하트 복사 시점이 어긋나지 않는다.

## 8. 초기값과 개인 채팅의 관계

개인 챗봇방은 저장된 `RoomProfile.baseAffection`을 표시하며, 기존 방에 값이 없으면 직렬화 기본값 50에서 시작한다. 과거 대화는 소급 분석하지 않는다. 정상 완료된 앞으로의 개인방 응답은 `[[affection:+N|-N]]` 표식으로 이 값을 바꿀 수 있다.

새 단톡방을 만들 때 각 참여자의 `RoomProfile.baseAffection`을 초기 하트값으로 복사한다. 값은 `0..100`으로 제한된다.

개인방과 각 단톡 세계선은 분기 후 서로 독립적이다. 단톡방에서 변한 값은 개인방의 기본 호감도로 역전파하지 않는다.

## 9. 현재 기준의 한계

현재 방식은 구현이 단순하고 캐릭터의 맥락을 모델이 해석할 수 있다는 장점이 있지만, 일관성을 보장하기 어렵다.

- 같은 사건에도 모델 실행마다 변화 여부나 숫자가 달라질 수 있다.
- 어떤 캐릭터는 작은 사건에 큰 숫자를 출력할 수 있다.
- 모델 판단 자체는 실행마다 달라질 수 있지만 큰 변화량은 턴당 `-3..+2` 제한으로 차단한다.
- 사용자는 왜 값이 변했는지 확인할 수 없다.
- 표식이 생략되면 관계상 중요한 사건이어도 값이 변하지 않는다.
- 모델 프롬프트 변경이 하트 변화 빈도에 간접적으로 영향을 줄 수 있다.

즉, 현재 하트는 **결정적 게임 규칙**이라기보다 **모델이 선택적으로 남기는 관계 메타데이터**에 가깝다.

## 10. 적용된 의미 기준

아래 표를 Gemini 관계 메타데이터 판단 기준으로 사용한다.

| 등급 | 권장 변화 | 사건 예시 |
|---|---:|---|
| 미세 긍정 | +1 | 반복해서 확인된 배려, 취향 존중, 의미 있는 공감 |
| 분명한 긍정 | +2 | 약속 이행, 신뢰 형성, 깊은 위로·관계 전환점 |
| 미세 부정 | -1 | 가벼운 무시, 작은 실망, 반복되는 불편함 |
| 분명한 부정 | -2 | 거짓말, 경계 침해, 공개적인 모욕, 신뢰 훼손 |
| 중대한 부정 | -3 | 배신, 강한 거부, 관계를 흔드는 사건 |

권장 안전 규칙:

- 한 사용자 턴당 캐릭터별 최종 변화량을 `-3..+2`로 제한한다. 현재 구현됨.
- 단순한 인사나 일상 대화는 기본적으로 `0`이다.
- 같은 행동이라도 캐릭터의 성격·욕구·경계에 따라 방향이 달라질 수 있다.
- 강한 변화는 대화 안에 실제 근거가 있을 때만 허용한다.
- 호감도 상승과 성적 수위는 동일한 개념으로 취급하지 않는다.
- 캐릭터가 상황극 안에서 연기한 감정과 지속 관계의 변화를 구분한다.
- 변화 이유의 별도 이벤트 로그는 아직 저장하지 않는다.

## 11. 관련 구현 위치

- 모델 출력 규약과 단톡 하트 표식 파싱: `android/app/src/main/java/com/sapiens/gagaodok/service/GroupConversationProtocol.kt`
- 개인방 호감도 표식과 비검열 규약: `android/app/src/main/java/com/sapiens/gagaodok/service/PersonalAffectionProtocol.kt`
- 정상 응답 완료 후 변화 적용: `android/app/src/main/java/com/sapiens/gagaodok/ui/screens/ChatRoomViewModel.kt`
- 세계선별 하트 합산 및 `0..100` 제한: `android/app/src/main/java/com/sapiens/gagaodok/model/GroupChatState.kt`
- 단톡방 생성 시 초기값 복사: `android/app/src/main/java/com/sapiens/gagaodok/data/GroupChatRoomFactory.kt`
- 개인 캐릭터 기본값: `android/app/src/main/java/com/sapiens/gagaodok/model/ChatRoom.kt`

## 12. 한 줄 요약

현재 호감도는 **개인방의 선택 Gemini 모델(단톡방은 3.7 Flash)이 관계 사건을 판단하고, 앱이 숨은 변화량을 턴당 `-3..+2`, 저장값 `0..100`으로 검증해 개인 기본값 또는 해당 세계선에 반영하는 시스템**이다.
