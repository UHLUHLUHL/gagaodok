## 1. 이게 무슨 앱인가

macOS SwiftUI 앱이다. **카카오톡 UI를 그대로 흉내 낸 AI 수학 과외 선생**이다.
사용자는 카카오톡을 쓰듯 방을 만들고 사진을 붙여넣고 질문한다. 답은 Gemini가 한다.

핵심은 **닮음이 기능**이라는 점이다. 사용자는 아이콘 하나, 여백 1pt까지 원본과 같기를
요구해 왔다. "비슷하게"가 아니라 "동일하게"다. 이 요구를 가볍게 보면 작업이 계속 되돌아온다.

- 저장소: `https://github.com/UHLUHLUHL/KakaoSapiens.git` (public)
- 앱 이름은 **가가오독**, 번들 ID와 데이터 폴더는 옛 이름(`KakaoSapiens`) 그대로다. 일부러 안 바꿨다.
  바꾸면 사용자의 기존 대화가 통째로 사라진다.
- 대화 저장 위치: `~/Library/Application Support/KakaoSapiens/`
- API 키: macOS 키체인 (`com.sapiens.kakaotalk.gemini-api-key`). **소스에 절대 넣지 않는다.**
  과거에 키가 커밋되어 히스토리를 다시 쓴 적이 있다.

## 2. 빌드하고 띄우기

```bash
swift build                 # 컴파일만 확인
./build_app.sh              # 번들 만들어 /Applications에 설치
./run.sh                    # 없으면 빌드하고 실행
```

`build_app.sh`의 `DISPLAY_NAME`이 번들 이름을 정한다. 여기를 바꾸면 `run.sh`의 `APP`도 같이 바꿔야 한다.
서명 인증서가 없어 ad-hoc 서명이라, 재설치할 때마다 키체인 허용 창이 뜬다. 사용자가 인증서를
만들면 `CODESIGN_IDENTITY="이름" ./build_app.sh`로 없앨 수 있다. 이건 사용자 몫이다.

## 4. 사용자가 기대하는 작업 방식

이게 이 문서에서 제일 중요하다. 지난 작업 내내 지켜 온 순서다.

**재고 → 고치고 → 눈으로 확인하고 → 사실대로 보고한다.**

- **추측한 숫자를 코드에 넣지 않는다.** 이 앱의 상수는 대부분 실제로 잰 값이다.
  한글 토큰 비율도, 아이콘 치수도, 다크 모드 색도 전부 화면이나 API 응답에서 뽑았다.
  처음에 2배 틀린 토큰 모델을 쓴 적이 있고, 그때 사용자에게 정정을 밝혀야 했다.
- **고쳤다고 말하기 전에 확인한다.** "고쳤습니다"라고 하고 안 고쳐진 적이 있어서,
  사용자가 특히 예민한 부분이다. 확인 못 했으면 못 했다고 쓴다.
- **틀렸으면 짧게 인정하고 넘어간다.** 길게 사과하지 않는다.
- **한국어로 답한다.** 사용자는 영어에 익숙하지 않다. 코드·경로·커밋 메시지는 영어 그대로.
- 사용자는 **자기 카카오톡을 직접 조작해 보라고 허락**한 적이 있다. 다만 범위는
  '나와의 채팅'으로 한정했다. 다른 사람과의 대화는 열지 않는다.

### 아이콘을 손대면 반드시 대조한다

```bash
tools/iconcheck/check.sh
```

앱을 띄우지 않고 뷰만 `ImageRenderer`로 그려, 원본 캡처와 **행 단위로** 폭을 비교한다.
차이가 ±0.5pt 이내면 맞은 것이다 (2배 화면의 1화소).

앱 창을 캡처해 확인하려 들지 마라. 창이 다른 데스크톱에 있으면 `screencapture`가
**전부 검은 그림**을 돌려주고, 그걸 모르면 "왜 안 보이지"로 시간을 버린다. 실제로 그랬다.

### 아이콘 치수 (전부 실제 카카오톡 캡처 실측, pt)

| 아이콘 | 크기 | 모양의 핵심 |

## 6. 이미 실패한 접근 — 다시 하지 말 것

시간을 많이 먹은 것들이다.

### 밝기 슬라이더가 창을 끌고 다니던 문제 (네 번 실패)

창이 `.titled + .fullSizeContentView`라 **위 약 28pt는 AppKit이 뷰 계층보다 위에서
타이틀바 드래그로 가져간다.** 그 안에 컨트롤을 두면 무슨 수를 써도 클릭이 창 이동에 먹힌다.

안 통한 것: `hitTest` 제외 → `mouseDown` 위치 검사 → NSView로 새로 만들기 → `mouseDownCanMoveWindow`.
통한 것: **`NSTitlebarAccessoryViewController`에 얹기.** AppKit이 정해 둔 방법이고, 여기 올린
뷰는 정상적으로 자기 이벤트를 받는다.

확인 방법: 슬라이더를 끄는 동안 창 좌표가 그대로인지 본다. `x=855 y=34`에서 안 움직였고
손잡이만 왼쪽으로 갔다.

### SF Symbols로 다 되지는 않는다 (그렇다고 다 손으로 그려도 안 된다)

수화기를 직접 그렸다가 경로가 스스로 겹쳐 뭉개진 덩어리가 됐다. **수화기·비디오·햄버거는
SF Symbols가 더 낫다.** 반대로 돋보기는 SF 쪽 손잡이가 2.75로 원본(1.5)의 두 배 가까워
혼자 뭉툭하다. 판단 기준은 취향이 아니라 **재 보고 정한다.**

### SwiftUI `Divider()`는 다크에서 순백(#FFFFFF)으로 그려진다

화면에서 재고 알았다. `HairlineDivider`를 쓴다. 이걸 고친 뒤에도 흰 줄이 남았는데,
그건 창 배경이 `.white`여서 반투명 선 뒤로 비친 거였다. 창 배경도 동적 색으로 바꿔야 한다.

### 한 Path에 몸통과 꼬리를 같이 넣으면 구멍이 뚫린다

감는 방향이 반대면 nonzero 채우기가 겹친 자리를 파낸다. 채팅 말풍선에 하얀 쐐기가
생겼던 이유다. 겹쳐 그리면(ZStack) 그럴 일이 없다.

### 한글 IME에서는 ⌘C가 문자로 "ㅊ"을 보낸다

문자로 비교하면 안 먹는다. `keyCode == 8`로 본다.

### 기타

- `grep -c`는 못 찾으면 종료 코드 1이다. `&&`로 이은 빌드·설치가 조용히 건너뛰어져
  "고쳤는데 안 됐다"는 헛소동이 났다.
- 아이콘 확대하려고 `sips`로 자를 때 좌표를 눈대중하지 말고 창 실측치에서 계산한다.

### 사용자가 요청했는데 아직 안 된 것

- **설정 아이콘.** "톱니바퀴 말고 '설정'에 어울리는 다른 걸로" 요청이 있었는데
  `KakaoMainWindowView.swift:108`은 아직 `gearshape`다.
- **모델 이름 글자색.** 헤더의 모델 표시가 회색이라 잘 안 보인다는 지적이 있었다.
  지금도 `onChatHeaderDim`을 쓴다. 실제로 어떻게 보이는지 확인하고 판단이 필요하다.
- 모델 선택 메뉴의 연노랑 선택 표시를 다른 것으로 바꿔 달라는 요청.

## 8. 조심할 것

- **원본 캡처에 개인정보가 섞여 있다.** 친구 목록 캡처에는 실명과 사진이 들어 있다.
  `tools/iconcheck/reference/`에는 아이콘만 오려서 넣었다. 공개 저장소라 캡처를 통째로 커밋하면 안 된다.
- **사용자 대화 내용을 밖으로 옮기지 않는다.** 요약·통계는 로컬에서 만든다.
- 키체인 읽기가 권한 때문에 막힐 수 있다. 막히면 우회하지 말고, 사용자가 직접 돌릴 수 있는
  도구를 만들어 넘긴다. 지난 작업에서 그렇게 했다.
