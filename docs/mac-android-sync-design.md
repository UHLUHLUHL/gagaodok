# macOS–Android 학습 데이터 동기화 설계안

## 상태

이 문서는 동기화 기능을 별도 단계에서 구현하기 위한 설계 문서다. 현재 태블릿 멘토 기능 구현 범위에는 Supabase와 동기화를 포함하지 않는다.

## 목표

macOS 앱과 Android 태블릿 앱이 같은 계정으로 로그인했을 때 다음 학습 데이터를 공유한다.

- 문제
- 채팅 메시지
- 필기 기록
- 이미지와 PDF
- 그래프 PNG와 수식 시각자료
- Obsidian export 관련 메타데이터

## Supabase 구성

- **Auth**: 사용자 계정과 기기 식별
- **Postgres**: 학습 데이터와 파일 메타데이터
- **Storage**: 이미지·PDF·PNG·필기 원본
- **Realtime**: 다른 기기에 변경 알림
- **RLS**: 사용자별 데이터 접근 제한

## 데이터 구조 초안

```text
learning_sessions
session_messages
ink_documents
ink_strokes 또는 ink_segments
attachments
visual_assets
sync_operations
devices
```

파일 원본은 Storage에 저장하고, DB에는 파일 ID·사용자 ID·세션 ID·Storage 경로·형식·크기·해시·생성 및 수정 시각을 저장한다.

## 동기화 방식

```text
기기 로컬 저장
      ↓
동기화 대기 큐
      ↓
Supabase 업로드
      ↓
Realtime 변경 알림
      ↓
다른 기기에서 최신 데이터 요청
      ↓
다른 기기의 로컬 저장소 반영
```

인터넷이 끊긴 상태에서도 앱은 계속 사용할 수 있어야 한다. 로컬에 먼저 저장하고, 연결이 복구되면 변경분을 업로드한다. 실패한 작업은 재시도 큐에 보관하며, 마지막 동기화 시각과 실패 상태를 사용자에게 표시한다.

## Realtime 사용 범위

- 새 메시지 등록 알림
- 필기 저장 완료 알림
- 새 첨부파일 등록 알림
- 다른 기기에서 수정된 학습방 표시

필기 중인 모든 펜 스트로크를 매번 전송하지 않는다. 일정 간격 또는 저장 시점에 묶어서 동기화해 데이터량과 충돌을 줄인다. Realtime은 변경 알림에 사용하고, 실제 데이터의 기준 저장소는 Postgres와 Storage로 유지한다.

## 충돌 처리

- **채팅 메시지**: 추가 전용으로 보존
- **필기**: 가능한 경우 스트로크 단위 병합
- **제목·메모**: 마지막 수정 우선
- **PDF·이미지**: 원본을 조용히 덮어쓰지 않고 새 버전 생성
- **그래프**: 명세와 PNG를 함께 버전 관리
- **동시 수정**: 자동 덮어쓰기 대신 충돌 상태 표시

## 파일 및 용량 관리

무료 플랜을 고려해 다음을 지원한다.

- 동일 파일 해시로 중복 업로드 방지
- Storage 사용량 표시
- 오래된 파일 정리 후보 표시
- 로컬 또는 Obsidian 백업 후 서버 파일 삭제
- DB에는 텍스트와 메타데이터를 중심으로 저장
- 다운로드한 파일은 기기에 캐시
- 동기화 실패와 재시도 상태 표시

## 보안

- 모든 데이터에 `user_id`를 포함한다.
- 로그인한 사용자의 데이터만 조회·수정하도록 RLS를 적용한다.
- Storage 파일도 사용자별 경로로 분리한다.
- 앱에 `service_role` 관리자 키를 포함하지 않는다.
- Gemini·OpenAI API 키는 동기화하지 않는다.
- 공개용 키를 사용하더라도 실제 접근 제한은 RLS로 강제한다.

## 구현 시점

이번 태블릿 멘토 기능 구현에서는 동기화를 구현하지 않는다. 추후 다음 순서로 별도 진행한다.

1. macOS·Android 공통 데이터 모델 확정
2. 양쪽 로컬 저장 구조 정리
3. Supabase 프로젝트 생성
4. DB·Storage·RLS 설정
5. 동기화 큐 구현
6. Realtime 변경 알림 연결
7. 오프라인·재연결·충돌 테스트
