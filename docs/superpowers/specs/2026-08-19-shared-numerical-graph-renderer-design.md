# 공용 수치해석 그래프 PNG 렌더러 설계

## 목표와 범위

macOS 수학 멘토의 채팅 답변과 Obsidian 문제 내보내기가 같은 로컬 그래프 엔진을 사용하도록 통합한다. 초등함수의 기존 `[GRAPH: ...]` 형식은 계속 지원하고, 음함수·수치적분으로 정의된 함수·1계 상미분방정식의 초기값 문제처럼 닫힌 꼴로 표현하기 어려운 그래프는 제한된 명세를 앱이 수치 계산하여 고해상도 PNG로 만든다.

이번 변경은 macOS 수학 멘토와 Obsidian 내보내기에만 적용한다. 동반자 모드와 Android는 변경하지 않는다. Python 런타임, 외부 그래프 API, 모델이 작성한 임의 코드 실행은 도입하지 않는다.

## 검토한 접근

### 1. Swift 기반 공용 수치해석 엔진 — 채택

모델은 계산 코드가 아니라 검증 가능한 그래프 명세를 반환한다. 앱은 제한된 수식 파서, 수치 샘플러, 로컬 WebKit/SVG 렌더러를 차례로 사용하여 PNG를 만든다.

- 장점: 오프라인 동작, 작은 배포 크기, 코드 서명 단순성, 임의 코드 실행 차단, 채팅과 Obsidian의 동일한 결과
- 단점: 지원할 수치해석 종류를 명시적으로 구현해야 함

### 2. Python·NumPy·SciPy·Matplotlib 번들

앱에 Python 런타임과 과학 계산 패키지를 함께 넣고 샌드박스 프로세스에서 실행한다.

- 장점: 폭넓은 기존 수치 알고리즘을 바로 활용 가능
- 단점: 큰 앱 용량, 아키텍처별 바이너리와 코드 서명 문제, 프로세스 격리와 자원 제한 필요, 모델 생성 코드를 실행할 경우 보안 위험

### 3. 모델이 계산한 좌표 배열을 직접 반환

모델이 수백~수천 개 점을 JSON으로 만들어 앱은 그림만 그린다.

- 장점: 앱 구현이 단순함
- 단점: 수치 정확도를 보장하기 어렵고 출력 토큰이 크게 늘며, 누락·잘림에 취약함

정확성·배포 안정성·보안을 함께 만족하는 1번을 사용한다.

## 공용 그래프 명세

중립적인 `MathVisualSpec`과 `MathVisualKind`를 새 공용 모델로 둔다. 기존 `ObsidianVisualSpec` 사용처는 호환 어댑터 또는 타입 별칭으로 유지하여 현재 미커밋 Obsidian 변경의 데이터 흐름을 깨지 않는다.

지원 종류는 다음과 같다.

- `function2D`: `y=f(x)` 명시적 함수
- `parametric2D`: `x=x(t), y=y(t)` 매개변수 곡선
- `implicit2D`: `F(x,y)=c` 음함수 등고선
- `integral2D`: `y(x)=y0+∫[a,b] g(x,t)dt` 형태의 수치적분 함수족
- `ode2D`: `y'=f(x,y)`, `y(x0)=y0` 형태의 1계 초기값 문제
- `surface3D`: `z=f(x,y)` 표면
- `coordinateDiagram`: 점·선분·라벨 도식

모든 종류는 ID, 제목, 캡션, 표시 범위, 수식 필드, 매개변수 범위, 초기점, 등고선 값, 점·선분 배열을 같은 구조로 가진다. 사용하지 않는 필드는 빈 문자열·빈 배열·기본값을 사용해 Gemini/OpenAI strict schema와 호환한다. 값은 유한성, 범위 순서, 문자열 길이, 배열 개수 제한을 통과해야 한다.

기존 `[GRAPH: ...]` 태그는 `function2D` 또는 `parametric2D` 공용 명세로 변환한다. 고급 그래프는 충돌과 쉼표 파싱 문제를 피하기 위해 별도의 JSON 기반 `[NUMERIC_GRAPH] ... [/NUMERIC_GRAPH]` 블록을 사용한다. 태그 안에는 실행 코드가 아니라 위 필드만 허용한다.

## 수식 평가와 수치해석

공용 `MathExpression`은 한 번 파싱한 구문 트리를 여러 변수 값으로 평가하도록 확장한다. 허용 문법은 사칙연산, 거듭제곱, 괄호, `x/y/t`, `pi/e`, 현재 허용된 초등함수로 한정한다. 파일 접근, 프로세스 실행, 네트워크, 동적 JavaScript, 사용자 정의 함수는 허용하지 않는다.

샘플러는 종류별로 다음 알고리즘을 사용한다.

- 명시적·매개변수 함수: 최대 1,200개 표본과 불연속 구간 분리
- 음함수: 제한된 격자에서 marching squares로 `F(x,y)-c=0` 선분 추출
- 수치적분: 평가 횟수와 재귀 깊이가 제한된 adaptive Simpson 적분
- 미분방정식: 초기점에서 좌우로 진행하는 RK4, 최대 스텝 수와 최소·최대 스텝 제한
- 3D 표면: 제한된 격자를 삼각형으로 투영하고 깊이 정렬, 색상 음영과 메쉬 적용

모든 계산에는 시간 대신 결정적인 평가 횟수 예산을 둔다. 정의역 오류, overflow, NaN, 예산 초과는 해당 선분을 끊거나 해당 시각자료만 실패시킨다. 임의의 식을 다른 함수로 대체하지 않는다.

## 렌더링과 데이터 흐름

`MathVisualRenderer`가 공용 명세를 받아 정규화된 곡선·선분·삼각형 payload를 만들고, 번들 내부 SVG 문서로 렌더링한다. 논리 폭은 1,200px, PNG 폭은 2,400px를 유지한다. 배경, 축, 눈금, 격자, 제목, 범례, 캡션, 주요 점·접선·변곡점 표시는 같은 스타일 시스템을 사용한다.

채팅 흐름은 다음과 같다.

1. 수학 멘토가 설명과 그래프 태그를 반환한다.
2. 응답 파서가 태그를 텍스트에서 분리하고 공용 명세로 변환한다.
3. 공용 엔진이 수치 계산과 PNG 렌더링을 수행한다.
4. PNG를 `image/png` 이미지 말풍선으로 붙인다.

Obsidian 흐름은 기존과 같다. 준비된 노트의 시각자료 명세를 공용 엔진으로 렌더링하고, 선택된 PNG만 `attachments/`에 저장한 뒤 wikilink를 Markdown에 넣는다. 시각자료가 없으면 기존 Markdown 결과는 변하지 않는다.

## 시스템 프롬프트 지침

수학 멘토 프롬프트는 다음 원칙을 명시한다.

- 닫힌 꼴 초등함수는 기존 `[GRAPH: ...]`를 우선 사용한다.
- 음함수, 수치적분 함수족, 1계 미분방정식 수치해처럼 고급 계산이 필요할 때만 `[NUMERIC_GRAPH]` 명세를 사용한다.
- 앱이 명세를 검증하고 로컬에서 수치 계산하여 PNG로 만든다는 사실만 안내하며, 모델이 Python을 실행한다고 주장하지 않는다.
- 원문과 풀이에서 도출되지 않은 함수·조건·특징점을 만들지 않는다.
- 축 범위, 초기값, 적분 범위, 등고선 값은 문제 조건과 일치해야 한다.
- 그래프가 이해에 실질적으로 도움이 되지 않으면 태그를 출력하지 않는다.

## 오류 처리

명세 파싱·검증·수치 계산·PNG 생성 중 하나가 실패해도 답변 텍스트나 Obsidian 노트 저장은 실패시키지 않는다. 채팅에서는 해당 이미지 말풍선만 제외하고 짧은 생성 실패 안내를 남긴다. Obsidian에서는 기존처럼 해당 시각자료만 제외하고 경고를 표시한다. 실패한 태그를 사용자 메시지에 그대로 노출하거나 틀린 대체 그래프를 만들지 않는다.

## 테스트와 완료 조건

구현은 TDD로 진행한다.

- 기존 `[GRAPH]` 태그가 같은 함수·범위로 공용 명세에 변환됨
- JSON 고급 태그의 정상·누락·악성 입력 검증
- 불연속 함수가 연결되지 않음
- 음함수 원의 표본점이 원 방정식에 허용 오차 내로 놓임
- 수치적분 결과가 알려진 해와 허용 오차 내에서 일치함
- `y'=y, y(0)=1`의 RK4 결과가 `e^x`와 허용 오차 내에서 일치함
- 2D·3D·음함수·적분·ODE 결과가 PNG 시그니처와 2,400px 폭을 가짐
- 채팅 첨부가 `.png`와 `image/png`를 사용함
- Obsidian 단일·일괄 내보내기가 같은 렌더러와 파일명을 사용함
- 번들 HTML에 외부 URL과 실행 가능한 외부 입력 경로가 없음
- 시각자료가 없는 기존 채팅·Markdown 출력에 회귀가 없음

최종 검증은 순수 계산 테스트, 렌더러 테스트, `swift build`, `./build_app.sh`, 설치 앱 코드 서명 확인, 설치 앱에서 초등함수·음함수·수치적분·ODE·3D 및 Obsidian 내보내기 실제 흐름 확인 순서로 수행한다.
