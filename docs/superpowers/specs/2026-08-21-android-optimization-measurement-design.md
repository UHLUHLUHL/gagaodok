# Android 최적화 측정 및 데이터 설정 통합 설계

## 목적

Android phone의 COMPANION 모드에서 비용, 명시적 캐시, 대화 압축, 말투 프롬프트의 실제 사용 결과를 2~3일 이상 개인정보 없이 측정한다. 사용자는 측정을 직접 시작하고 종료하며, 종료한 측정 회차를 계속 보존하고 언제든 JSON 하나로 내보낼 수 있다.

이 기능은 백그라운드 작업이 아니다. 측정 중 실제 AI 요청과 캐시 판단이 발생할 때만 작은 로컬 집계값을 갱신한다. 모델 요청 본문은 바꾸지 않으며 추가 API 호출도 하지 않는다.

## 범위

- 적용 대상: Android `phone` 변형의 `COMPANION` 모드
- 설정 화면의 데이터 관련 항목 통합
- 여러 최적화 측정 회차의 시작, 종료, 보존, 내보내기
- 기존 사용량 저장 데이터 및 이미 생성된 v1 JSON과의 호환
- 대화 원문을 저장하지 않는 집계형 계측

다음은 변경하지 않는다.

- Android 태블릿 멘토 변형과 멘토 대화 로직
- macOS 앱
- Obsidian 및 태블릿 필기 흐름
- 모델 프롬프트, 캐시 정책 수치, 대화 압축 정책 자체
- 서버 업로드 및 자동 원격 분석

## 검토한 방식

### 1. 시작·종료 시점의 사용량 스냅샷만 저장

구현은 가장 작지만 캐시를 건너뛴 이유, 생성 실패, 프롬프트 구성 비중을 사후에 복원할 수 없다. 4,600토큰 기준의 타당성을 판단하기에 부족하므로 채택하지 않는다.

### 2. 요청별 원시 이벤트를 모두 저장

가장 자세하지만 파일이 지속적으로 커지고 요청 순서와 상대 시각이 불필요하게 세밀하게 남는다. 분석 목적보다 많은 데이터를 보존하므로 채택하지 않는다.

### 3. 측정 회차별 집계 저장 — 채택

각 요청과 캐시 판단 시 미리 정한 카운터와 토큰 구간만 누적한다. 비용 판단에 필요한 근거는 남기면서 파일 크기와 개인정보 위험을 제한한다. 측정이 끝나면 회차를 고정하고 다음 회차와 함께 보존한다.

## 사용자 흐름

설정 화면의 기존 `API 사용 금액`, `대화방별 사용 내역`, `사용 패턴 통계 내보내기`, `사용량 초기화`를 하나의 `데이터` 영역으로 모은다. API 키는 보안 설정이므로 기존 별도 영역에 둔다.

데이터 영역은 다음 순서로 표시한다.

1. 누적 API 사용 금액과 토큰 요약
2. 대화방별 사용 내역
3. 최적화 측정 상태
4. 분석 데이터 내보내기
5. 사용량 초기화

측정 상태는 세 가지다.

- 측정 전: `최적화 측정 시작` 버튼 표시
- 측정 중: 경과 일수와 집계된 요청 수를 표시하고 버튼을 `측정 종료`로 변경
- 측정 완료: 최근 회차의 기간과 요청 수를 표시하고 `새 측정 시작` 제공

측정 중에도 현재까지의 JSON을 내보낼 수 있다. 종료하면 종료 시각을 기록하고 결과를 고정한다. 새 측정을 시작해도 완료된 과거 회차는 삭제하지 않는다. 분석 기록은 별도의 확인 절차를 거친 `측정 기록 삭제`에서만 지운다.

`사용량 초기화`는 기존 토큰 장부만 초기화한다. 측정 회차와 채팅은 지우지 않으며, 실행 전 이 차이를 설명하는 확인창을 표시한다.

## 저장 구조

새 `OptimizationMeasurementStore`가 앱 내부 JSON 파일을 소유한다. 직렬화 구조에는 `schemaVersion`, 선택적인 활성 회차, 완료 회차 목록을 둔다. 기존 파일이 없으면 빈 상태로 시작하고 알 수 없는 추가 필드는 무시한다.

각 `MeasurementRun`은 로컬에서만 다음 정보를 가진다.

- 내부 회차 ID
- 시작 시각과 선택적 종료 시각
- 시작 당시 정책 스냅샷
- 모드별·익명 방별 집계
- 요청 사용량 집계
- 캐시 판단 집계
- 프롬프트 구성 추정 집계

정책 스냅샷에는 모델 식별자, 최소 캐시 추정 토큰 4,600, 캐시 TTL 900초, 연속 사용 창 300초, 갱신 꼬리 최소 2,000토큰, 대화 압축 정책 값을 기록한다. 이후 앱 정책이 바뀌어도 각 회차를 올바르게 비교할 수 있어야 한다.

완료 회차는 자동 삭제하지 않는다. 각 회차는 원시 대화나 요청 이벤트가 아닌 합계와 히스토그램만 가지므로 크기는 제한적이다.

## 측정 항목

### 요청 결과

- 요청 수와 사용량 미수신 요청 수
- 서버 보고 입력, 캐시 입력, 출력 토큰 합계
- 캐시 적중 요청 수
- 모델별 합계

### 캐시 판단

- 전체 캐시 판단 횟수
- 최소 토큰 미달
- 연속 사용 조건 미달
- 기존 캐시 그대로 사용
- 새 꼬리가 작아 갱신하지 않음
- 만료 임박 갱신 시도
- 생성 또는 갱신 성공
- HTTP 실패와 로컬 예외
- 생성한 실제 캐시 토큰과 보관 token-hours

예상 접두사 토큰은 원값 목록 대신 다음 구간별 횟수로 저장한다.

- 0~4,095
- 4,096~4,599
- 4,600~8,191
- 8,192~16,383
- 16,384 이상

이 구간을 통해 4,600 안전선 때문에 공식 최소치 이상인 요청을 얼마나 건너뛰는지 판단한다.

### 시간과 재사용

- 이전 사용자 요청과의 간격 구간: 1분 미만, 1~5분, 5~15분, 15~30분, 30분 초과
- 생성된 캐시별 적중 요청 수의 히스토그램
- TTL 안에서 첫 적중까지의 간격 구간
- 다음 요청 또는 교체 시점에 확인된, 한 번도 적중하지 않고 만료·교체된 캐시 수

시간은 내부 계산을 위해 로컬 시각을 사용하되 내보내기에서는 절대 시각을 제거한다. 회차는 `run-1`, `run-2`처럼 표시하고 기간은 초 또는 분 단위 길이만 내보낸다.

### 프롬프트 구성

실제 요청 문자열을 저장하지 않고 기존 토큰 추정기로 다음 합계만 기록한다.

- 안정적인 시스템 지침
- 캐릭터 말투 규칙과 예시
- 장기기억 요약
- 최근 원문 대화
- 반복 억제 동적 지침
- 이미지·PDF 추정 토큰

서버가 보고한 전체 입력 토큰과 로컬 구성 추정치는 별도로 보존한다. 추정치가 실제 청구량인 것처럼 표시하지 않는다.

## 데이터 흐름

1. 사용자가 측정을 시작하면 저장소가 정책 스냅샷과 시작 시각을 가진 활성 회차를 만든다.
2. COMPANION 요청을 조립할 때 기존 문자열을 변경하지 않고 각 구성의 추정 토큰만 저장소에 전달한다.
3. 응답의 `usageMetadata`를 기존 `TokenUsageStore`에 기록한 직후 같은 숫자를 활성 측정 회차에 누적한다.
4. 캐시 판단 함수는 각 조기 반환과 생성 결과를 열거형 사유로 저장소에 전달한다.
5. 측정을 종료하면 종료 시각을 기록하고 활성 회차를 완료 목록으로 이동한다.
6. 내보낼 때 채팅 저장소에서 회차 시간 범위 안의 사용자 메시지 시각만 읽어 간격 통계를 계산하고, 저장된 집계와 합친다.
7. 모든 회차와 현재 누적 사용량 요약을 하나의 v2 JSON으로 저장하고 Android 공유창을 연다.

## 개인정보와 비용 경계

저장 및 내보내기에서 다음을 금지한다.

- 사용자와 챗봇의 대화 원문
- 첨부파일 내용과 파일명
- 방 이름, 캐릭터 이름, 방 UUID
- API 키
- 절대 요청·대화 시각
- 시스템 프롬프트와 말투 규칙 원문

방은 회차 안에서 `room-1` 형태로 익명화한다. 측정은 모델 요청에 어떤 텍스트도 추가하지 않으므로 토큰 비용과 캐시 지문에 영향을 주지 않는다. 네트워크 요청도 추가하지 않는다.

## 오류 처리

- 앱이 종료되어도 활성 회차는 유지하고 다음 실행에서 이어간다.
- 저장 실패는 대화를 실패시키지 않는다. 설정 화면에 측정 저장 오류 상태를 표시한다.
- 캐시 HTTP 실패는 응답 본문을 저장하지 않고 실패 횟수만 센다.
- 측정 중 내보내기는 현재 시각을 임시 종료점으로 사용하지만 회차 상태를 종료하지 않는다.
- 활성 회차가 있는데 다시 시작하려는 요청은 만들지 않고 현재 회차를 보여준다.
- 과거 v1 내보내기 파일은 가져오는 대상이 아니므로 마이그레이션하지 않는다. 앱 내부 기존 토큰 장부는 그대로 읽는다.

## 테스트와 검증

TDD로 다음을 먼저 검증한다.

- 측정 시작, 앱 재생성 후 복원, 종료, 새 회차 시작, 과거 회차 보존
- 측정 중이 아닐 때 어떤 집계도 바뀌지 않음
- phone COMPANION만 기록되고 멘토 요청은 기록되지 않음
- 캐시 판단 사유와 토큰 구간 집계
- v2 JSON에 금지 문자열, UUID, 절대 시각이 포함되지 않음
- 측정 중 내보내기가 회차를 종료하지 않음
- 사용량 초기화가 측정 기록을 지우지 않음
- 기존 저장 파일이 없어도 동작하고 새 필드가 추가된 저장 파일을 읽음

이후 Android phone 단위 테스트, 릴리스 빌드, 동일 서명 확인, 데이터 보존 덮어설치를 수행한다. 실제 기기에서 시작, AI 요청, 중간 내보내기, 종료, 재시작, 통합 JSON 내보내기 흐름을 검증한다.

## 완료 기준

- 데이터 관련 UI가 하나의 데이터 영역에 모인다.
- 사용자가 원하는 시점에 측정을 시작하고 종료할 수 있다.
- 완료된 여러 회차가 명시적 삭제 전까지 보존된다.
- 측정 중과 종료 후 언제든 단일 JSON을 내보낼 수 있다.
- JSON만으로 정책별 비용, 캐시 판단, 재사용, 프롬프트 구성 비중을 비교할 수 있다.
- 측정 자체가 API 호출, 프롬프트 토큰, 캐시 접두사 또는 백그라운드 배터리 사용을 늘리지 않는다.
