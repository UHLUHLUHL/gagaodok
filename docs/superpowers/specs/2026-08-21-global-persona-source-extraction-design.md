# 캐릭터 말투 원출처 추출 및 반복 제어 설계

작성일: 2026-08-21
브랜치: `codex/persona-repetition-control`

## 목표와 범위

Android phone 변형의 `COMPANION` 모드에서 캐릭터 이름이나 링크만으로 신뢰도 높은
말투 규칙을 처음부터 생성한다. 특정 작품이나 캐릭터를 하드코딩하지 않으며, 모든
애니메이션 캐릭터에 같은 출처 우선순위와 표본 선별 규칙을 적용한다.

공식 영상이 존재하면 공식 배급사·제작사·방송사 영상의 자막을 가장 강한 원본 증거로
사용한다. 조사에는 충분한 대사를 사용하되 실제 채팅에는 압축된 규칙과 소수의 다양한
대표 표본만 넣어 토큰 비용, 문구 복사, 말버릇 과적합을 함께 줄인다.

멘토 모드, 태블릿 필기, Obsidian 흐름, macOS 앱은 변경하지 않는다. 장기 대화 압축의
`150/20/50` 정책도 이번 작업에서 수치 변경하지 않고 회귀 검증만 한다.

## 확인된 문제

- 공통 조사 지침은 최대 20개, COMPANION 추가 지침은 최대 12개를 요구하고 파서는
  다시 20개까지 허용해 표본 상한이 일관되지 않다.
- 검색·대사 채집·말투 분석을 한 요청에서 처리하므로, 출처가 부정확한 대사가 규칙에
  곧바로 반영될 수 있다.
- 현재 출처 기록은 제목 문자열뿐이어서 대사와 URL·시각을 연결해 검증할 수 없다.
- 로컬 중복 제거는 띄어쓰기와 대소문자를 제외하고 완전히 같은 문장만 제거한다. 같은
  시작 표현이나 유사 문장은 여러 표본으로 남아 빈도를 부풀릴 수 있다.
- 실제 채팅에는 조사 결과의 첫 8개가 들어간다. 서로 다른 상황·길이·종결을 대표하도록
  선별된 8개가 아니다.
- 사용자가 영구 억제한 표현도 매 요청의 비캐시 동적 지침에 들어간다.
- Gemini 3.7 Flash의 공식 명시적 캐시 최소 크기는 4,096토큰인데 앱의 사전 판단은
  1,200토큰이라 거절될 캐시 생성을 불필요하게 시도할 수 있다.
- GPT-5.6 Luna의 앱 내 단가가 최신 공식 인하 가격과 다르다.
- 현재 테스트는 지침 문자열과 로컬 반복 감지만 검증하며, 출처 신뢰도·표본 다양성·
  토큰 손익·장기 재현성에 대한 비교 검증은 없다.

## 전역 출처 정책

출처는 캐릭터가 아니라 자료의 소유권과 번역 권위로 분류한다.

1. `OFFICIAL_LOCALIZED_VIDEO`: 한국 공식 배급사·제작사·방송사 영상의 한국어 자막
2. `OFFICIAL_ORIGINAL_VIDEO`: 원 제작사·공식 작품 채널의 원어 영상·자막
3. `OFFICIAL_TEXT`: 공식 작품 사이트, 공식 출판물, 공식 대본·인터뷰
4. `REPUTABLE_SECONDARY`: 신뢰 가능한 언론·데이터베이스의 인용 자료
5. `UNVERIFIED`: 위키, 커뮤니티, 밈, 출처를 역추적할 수 없는 문구

상위 공식 자료가 존재하면 하위 자료를 공식 대사처럼 섞지 않는다. 비공식 자료는 공식
자료가 부족할 때 후보로만 표시하며, 사용자 확인 없이 높은 확신도로 저장하지 않는다.
공식 자료가 적으면 표본 수를 억지로 채우지 않고 부족함을 그대로 보여준다.

동명이인, 다른 작품·시즌, 더빙판, 극장판과 TV판을 구분한다. 여러 공식 한국어 번역이
다르면 한 문장으로 합치지 않고 판본과 출처를 각각 남긴다.

## 조사 파이프라인

### 1. 원출처 탐색

캐릭터 이름으로 찾을 때 Google 검색 그라운딩을 사용해 최대 8개의 후보 출처를 찾는다.
검색어에는 작품명, 캐릭터명, 공식 채널·배급사·제작사, 예고편·하이라이트·인터뷰 같은
자료 유형을 포함한다. 사용자가 직접 URL을 입력하면 해당 URL을 먼저 검증하며, 충분한
공식 자료이면 탐색 요청을 생략할 수 있다.

탐색 결과는 제목만이 아니라 URL, 게시자, 자료 유형, 공식성 근거, 언어, 작품·판본을
구조화해 반환한다. 공식성 근거가 불명확한 자료는 자동으로 공식 등급을 받지 않는다.

### 2. 공식 영상·문서에서 증거 추출

YouTube URL은 일반 URL 문서 읽기가 아니라 Gemini 영상 입력으로 전달한다. 별도 자막
트랙이 없더라도 음성과 화면에 삽입된 자막을 함께 분석한다. 한국 공식 영상에서는 원어를
임의 번역하지 않고 화면의 공식 한국어 자막을 우선한다.

한 번의 조사에서 공식 영상은 최대 5개, 분석하는 영상 길이는 합계 15분을 기본 상한으로
한다. 짧은 예고편·캐릭터 하이라이트를 우선하고, 긴 영상은 필요한 구간을 지정할 수 있을
때만 사용한다. 자막 누락을 줄이기 위해 짧은 공식 영상은 기본 영상 샘플링보다 높은 자막
판독용 샘플링을 사용하되 실제 API 토큰 사용량을 기록한다.

텍스트·이미지·PDF 공식 자료는 URL context로 읽는다. 공식 영상과 공식 문서가 함께 있으면
영상 자막을 우선하고 문서는 교차 확인에 사용한다.

각 증거는 다음 정보를 갖는다.

- 대사 원문
- 말한 캐릭터
- 출처 URL과 제목
- 출처 등급과 판본·언어
- 영상이면 타임스탬프
- 주변 상황을 나타내는 짧은 문맥 태그
- 모델의 추출 확신도

목표는 서로 다른 실제 대사 40개, 최대 48개, 권장 최소 20개다. 공식 자료에서 확인되는
대사가 그보다 적으면 확인된 수만 사용한다.

### 3. 로컬 정규화와 다양성 선별

모델의 “중복이 아니다”라는 판단에만 의존하지 않는다. 로컬 순수 함수가 다음을 수행한다.

- 공백·문장부호 차이만 있는 완전 중복 제거
- 같은 시작절과 높은 단어 n-gram 겹침을 가진 유사 대사 묶기
- 같은 출처의 연속 자막 조각을 하나의 논리 대사로 결합
- 다른 공식 판본의 번역 차이는 제거하지 않고 별도 판본으로 보존
- 평상시·질문·동의·거절·장난·친밀함·분노·당황 등 문맥 태그 분산
- 짧은 답, 중간 길이, 긴 문장의 길이 분산
- 종결·호칭·감정 부호·시작 표현의 분산

분석에는 공식성이 높은 순서로 다양하게 선별된 24~40개를 사용한다. 단순히 검색 결과의
앞부분을 자르는 방식은 사용하지 않는다.

### 4. 최초 고품질 규칙 생성

선별이 끝난 뒤 별도의 저사고량 분석 요청을 한 번 실행한다. 분석 모델에는 대사와 함께
출처 등급, 문맥 태그, 유사 표본 묶음 크기, 관찰된 반복 횟수를 전달한다. 이 단계는 사용자가
별도의 재분석 버튼을 누르지 않아도 최초 `찾기` 흐름 안에서 완료한다.

규칙은 대표 문구보다 다음 순서로 작성한다.

1. 문장 구조, 절의 연결과 호흡·리듬
2. 1인칭, 상대 호칭, 높임 수준과 상황별 전환
3. 감정별 표현 강도와 질문·거절·동의 방식
4. 문장 길이와 문장부호
5. 어휘와 말버릇

빈도는 근거 없이 항상·자주로 단정하지 않는다. `관찰 횟수/관련 표본 수`와 서로 다른
문맥 수를 근거로 항상·자주·가끔·드물게를 구분한다. 단일 장면이나 유사 중복 묶음에서만
반복된 표현은 대표 말버릇으로 승격하지 않는다.

`다듬기`와 수동 `재분석`은 유지하지만 보조 흐름으로 취급한다. 최초 조사 결과만으로도
출처가 검증된 표본과 완성된 규칙이 편집 화면에 채워져야 한다.

## 저장 형식과 호환성

기존 `PersonaStyle.samples: List<String>`는 유지해 과거 저장 파일과 수동 편집 흐름을
깨지 않는다. 새 버전은 기본값이 있는 선택 필드로 표본 증거를 추가한다.

```text
PersonaSampleEvidence
- text
- speaker
- sourceUrl
- sourceTitle
- sourceTier
- edition
- language
- timestampSeconds?
- contextTag
- confidence
```

이전 JSON에는 새 필드가 없으므로 빈 목록으로 읽는다. 사용자가 대사 문장을 직접 수정하면
원문과 정확히 일치하지 않는 증거 연결은 제거해 수정된 문장을 공식 인용처럼 보이지 않게
한다. 출처와 연결되지 않은 수동 대사는 계속 사용할 수 있지만 `직접 입력`으로 표시한다.

## 채팅용 말투 압축

조사·분석 표본과 매 요청에 넣는 표본을 분리한다. 채팅 시스템 프롬프트에는 다음만 넣는다.

- 구조화된 말투 규칙
- 출처·상황·길이·종결이 서로 다른 대표 표본 최대 8개
- 표본 원문을 복사하지 말고 상황에 맞는 새 문장을 만들라는 지침

대표 표본은 첫 8개가 아니라 로컬 다양성 점수로 선택한다. 개수 상한과 함께 원문 예시
토큰 예산을 적용해 긴 대사 8개가 프롬프트를 과도하게 키우지 않게 한다. 초기 예산은
`TokenEstimator` 기준 900토큰으로 두고, 실제 Gemini `usageMetadata`와 비교해 검증한다.

말투 규칙과 대표 표본은 방별 안정 시스템 프롬프트에 있으므로 장기 대화 요약과 독립적으로
유지된다. 대화 요약에는 관계·약속·사건·감정 상태를 남기되, 챗봇 자신의 반복된 문구나
정체성은 넣지 않는 현재 원칙을 보존한다.

## 반복·억제 지침의 위치

사용자가 편집 화면이나 말풍선 메뉴에서 영구 억제한 표현은 `PersonaStyle`의 안정 시스템
프롬프트에 넣는다. 말투를 편집하면 기존 캐시는 한 번 무효화되지만, 이후에는 억제 규칙도
함께 캐시된다.

최근 8개 챗봇 답변에서 자동 감지된 반복 표현만 최신 사용자 턴의 가변 suffix에 넣는다.
자동 감지 결과는 저장하지 않고 장기 요약에도 넣지 않는다. 따라서 캐시 접두사를 유지하면서
현재 반복만 교정한다.

## 토큰·캐시·비용 정책

말투 조사는 일반 채팅과 분리된 사용자 시작 작업이다. 기본 흐름은 최대 세 단계다.

1. 공식 출처 탐색: 검색 사용, medium 사고량, 짧은 구조화 출력
2. 증거 추출: 공식 영상·문서 입력, medium 사고량, 최대 48개 증거
3. 규칙 생성: 정리된 24~40개 입력, low 사고량, 압축된 규칙 출력

사용자가 공식 URL을 직접 제공해 출처 탐색이 불필요하면 첫 단계를 생략한다. 각 단계의
입력·도구·사고·출력 토큰을 현재 사용량 장부에 별도로 기록한다. 검색 도구 호출 수와
동영상 입력 사용량도 누락하지 않는다.

조사 비용은 한 번 늘 수 있지만, 채팅에 넣는 대표 표본과 토큰 예산은 제한하므로 장기적인
턴당 비용은 늘리지 않는 것을 목표로 한다. 구현 시 기존 12개 조사/8개 첫 표본 방식과 새
방식을 같은 고정 자료로 비교해 다음을 계산한다.

- 최초 조사 총 토큰과 예상 USD
- 규칙과 대표 표본의 시스템 프롬프트 토큰
- 캐시 생성, 캐시 읽기, 일반 입력의 손익분기 요청 수
- 10·50·150·300턴 누적 비용
- 캐시 적중이 전혀 없는 보수적 상한

Gemini 명시적 캐시는 공식 최소 4,096토큰보다 안전 여유가 있는 추정 4,600토큰부터 생성을
시도한다. 기존처럼 짧은 간격의 두 번째 요청 이후에만 만들고, 캐시 쓰기와 15분 보관료를
포함했을 때 후속 요청에서 이익이 생기는지 시뮬레이션한다. 갱신 꼬리와 TTL 기준은 실측
비교 없이 변경하지 않는다.

OpenAI에서는 안정 시스템 프롬프트와 과거 대화 접두사를 그대로 유지하고 동적 반복 지침을
마지막 사용자 턴에만 붙인다. `cached_tokens` 실측으로 적중 여부를 판정한다.

Gemini 3.7 Flash와 GPT-5.6 Luna의 앱 내 단가는 구현 시점의 공식 모델 가격으로 갱신하고,
단가 테스트를 추가한다. 가격이 다시 바뀌어도 한 위치에서 수정할 수 있는 현재 모델별 단가
구조는 유지한다.

## 실패 처리

- 공식 자료를 찾지 못하면 낮은 확신도를 표시하고 비공식 후보를 자동 확정하지 않는다.
- YouTube 영상 입력이 미리보기 제한, 지역 제한, 429 또는 지원 오류로 실패하면 공식 텍스트·
  이미지 자료로 대체한다. 팬 자료로 조용히 강등하지 않는다.
- 영상에서 화자를 특정하지 못한 문장은 표본에서 제외한다.
- 자막 화면과 음성 추정이 충돌하면 한국 공식 영상에서는 화면 자막을 우선하고 충돌을 기록한다.
- 20개 미만만 확인돼도 실패로 만들지 않고 확인된 개수와 부족 이유를 보여준다.
- 단계 중간 실패는 기존 저장된 말투를 덮어쓰지 않는다. 전체 조사 성공 후 편집 상태만 바꾸며,
  사용자가 `저장`해야 방 설정에 반영한다.

## 테스트와 검증

TDD 순수 단위 테스트는 다음을 검증한다.

- 출처 등급과 공식 자료 우선 정렬
- 48개 조사, 24~40개 분석, 8개 런타임 상한
- 완전 중복과 같은 시작·유사 n-gram 표본 묶기
- 상황·길이·종결 다양성을 가진 대표 표본 선택
- 판본이 다른 공식 번역은 중복으로 제거하지 않음
- 기존 PersonaStyle JSON의 새 증거 필드 기본값
- 수동 수정된 대사의 증거 연결 해제
- 영구 억제 표현은 안정 프롬프트, 자동 반복은 가변 suffix에만 존재
- 동적 지침이 캐시 지문과 저장 대화를 바꾸지 않음
- 4,096토큰 미만 Gemini 캐시 생성 방지와 4,600 추정 여유
- 공식 최신 모델 단가와 캐시 손익 계산
- 장기 요약이 캐릭터 자신의 말버릇을 기억으로 보존하지 않음

네트워크 경계 테스트는 구조화 응답 파싱, 출처 URL·타임스탬프 보존, 부분 실패를 검증한다.
실제 API 키를 사용하는 선택적 검증에서는 특정 캐릭터를 제품 규칙에 하드코딩하지 않고,
공개 공식 영상 URL을 입력해 화면 자막에서 증거가 추출되는지 확인한다. 저작권이 있는 긴
대사 원문은 테스트 fixture나 저장소에 포함하지 않는다.

Android phone 테스트와 release 빌드를 수행한다. 실제 기기가 연결돼 있으면 COMPANION
말투 편집에서 공식 영상 조사 → 최초 규칙 생성 → 저장 → 장기 대화 반복 제어 흐름을 확인한다.
기기가 없으면 API·UI 실기 검증 제한을 명시한다.

## 완료 기준

- 어떤 애니메이션 캐릭터에도 같은 출처 정책이 적용되고 특정 작품이 하드코딩되지 않는다.
- 공식 영상이 있으면 일반 팬 검색 결과보다 해당 영상 자막이 우선된다.
- 대사마다 검증 가능한 URL과 영상 타임스탬프가 보존된다.
- 공식 자료가 충분하면 최대 48개를 조사하고 24~40개로 최초 규칙을 만든다.
- 실제 채팅에는 다양한 대표 표본 최대 8개와 토큰 예산만 들어간다.
- 영구 억제 규칙은 캐시 가능하고 자동 반복 보정은 캐시 접두사를 깨지 않는다.
- 장기 요약이 관계 기억은 보존하지만 과거 챗봇의 잘못된 말버릇은 강화하지 않는다.
- 기존 저장 데이터와 멘토·태블릿·macOS 동작이 유지된다.
- 현재 방식과 새 방식의 토큰·비용 비교가 재현 가능하고, 가격과 캐시 최소값이 공식 수치와
  일치한다.
