# Android 단톡방·평행세계·하트게이지 사양

상태: 구현 기준 사양. 사용자와 합의한 B안(개인방과 단톡방 완전 분리)을 따른다.

## 범위

- Android `phone` 변형의 `COMPANION` 모드에 단톡방, 평행세계, 하트게이지를 추가한다.
- `tabletMentor`, 수학 멘토 모드, macOS, Obsidian 흐름은 변경하지 않는다.
- 기존 개인방의 말투, 나레이션 분리, 캐싱, `turnId`, `canonicalText` 동작은 그대로 유지한다.
- Figma 파일 `UJZoCC2StSwwNSVVFSi1mx`의 기존 `Page 1`만 사용한다. 새 파일과 새 페이지는 만들지 않는다.

## 데이터 불변식

1. 개인방은 `RoomProfile.baseAffection`을 가진다. 옛 저장 데이터는 `50`으로 마이그레이션한다.
2. 단톡방 생성 시 선택한 개인방 각각의 현재 `baseAffection`을 기본 세계선의 하트값으로 복사한다.
3. 단톡방의 하트 변화는 개인방 `baseAffection`에 역으로 반영하지 않는다.
4. 새 세계선은 분기 시점의 대화 기록, 요약, 참여자별 하트값을 복사한 뒤 독립적으로 변한다.
5. 개인방 파일과 단톡방 세계선 파일은 서로 다른 이름을 사용한다. 단톡방 사이와 세계선 사이에도 상태가 섞이지 않는다.
6. 세계선을 전환하면 해당 세계선의 대화 기록과 하트값이 함께 복원된다.
7. 참여자는 기존 개인 캐릭터 라이브러리에서 중복 없이 두 명 이상 선택한다.
8. 단톡방 생성 직후 모든 세계선의 대화는 빈 배열이다. 사용자가 첫 메시지를 보내기 전에는 모델 요청과 자동 인사를 실행하지 않는다.

## 단톡방 응답 규약

- 한 사용자 턴당 Gemini 3.7 Flash 요청은 한 번만 보낸다. 참여자 수만큼 요청을 반복하지 않는다.
- 단톡방 전용 합성 페르소나가 참여자 이름, ID, 개별 페르소나와 출력 규약을 모델에 전달한다.
- 대사는 따옴표 안의 `[[speaker:<ROOM_UUID>]]` 표식으로 화자를 식별한다. 표식은 저장할 원문에는 남겨 다음 요청의 구조를 유지하지만 화면 텍스트에서는 제거한다.
- 하트 변화는 `[[heart:<ROOM_UUID>:+N]]` 또는 `[[heart:<ROOM_UUID>:-N]]`로 받으며 화면에는 표시하지 않는다. 값은 활성 세계선에서만 `0..100`으로 제한해 적용한다.
- 표식이 빠진 말풍선은 같은 AI 턴의 직전 유효 화자를 이어받는다. 첫 말풍선부터 표식이 없으면 첫 참여자로 안전하게 표시하되 원문은 손실하지 않는다.
- 나레이션은 기존 `RoleplayParser`의 가운데 안내문 표현을 그대로 사용하며 화자 아바타를 붙이지 않는다.

## 화면과 모션

### 단톡방 만들기

- 채팅 탭의 작성 버튼에서 `새 대화 상대`와 `새 단톡방`을 선택한다.
- 단톡방 화면은 기존 개인 캐릭터만 다중 선택할 수 있고, 선택 수와 생성 가능 상태를 즉시 보여 준다.
- 두 명 이상 선택해야 생성 버튼이 활성화된다. 기본 방 제목은 선택한 이름을 쉼표로 연결한 값이다.

### 단톡방

- 헤더는 겹친 참여자 아바타, 단톡방 이름, 참여자 수, 세계선 진입점을 보여 준다.
- AI 대사에는 화자 개인방의 이름과 아바타를 붙인다. 나레이션은 기존 가운데 안내문을 쓴다.
- 하트게이지는 기본적으로 `♥ 평균값`의 작은 pill이고 누르면 참여자별 카드로 펼쳐진다.
- 접기·펼치기는 Figma `Heart gauge` 컴포넌트의 Smart Animate 기준인 `300ms ease-out`을 Compose에서 재현한다. 목록 앵커가 튀지 않아야 한다.
- 세계선 전환은 `220ms ease-out`의 짧은 fade/수평 이동으로 대화와 하트 패널을 함께 바꾼다.
- 새 세계선은 현재 세계선에서 분기한다는 설명, 이름 입력, 현재 하트와 대화 상속 표시를 제공한다.
