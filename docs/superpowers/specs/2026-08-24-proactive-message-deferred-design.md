# Android 성인모드 선톡 보류 설계

## 문서 상태

- 상태: **구현 보류 / 재검토용 설계 초안**
- 대상: Android phone `COMPANION` 성인모드
- 기준 모델: 사용자가 별도로 요청하기 전까지 Gemini 3.7 Flash만 대상으로 한다.
- 이 문서는 구현 승인이 아니다. 선톡 코드, 예약 작업, 알림, 프롬프트는 변경하지 않는다.

## 보류 이유

선톡은 마지막 메시지 이후의 경과 시간만으로 결정할 수 없다. 진행 중인 상황극에서 사용자가
현실의 다른 일을 하려고 앱을 잠시 떠난 경우, 캐릭터가 새 대화를 시작하거나 장면을 임의로
진행하면 대화 속 시간과 현실 시간이 뒤섞이고 몰입이 깨진다.

따라서 선톡을 구현하려면 먼저 각 세계선의 장면 상태, 캐릭터가 사용자의 응답을 기다리는지,
사용자가 현재 선택한 세계선, 선톡의 종류와 발송 시점까지 함께 다루는 구조가 필요하다.
판단이 애매할 때는 발송하지 않는 것을 초안의 기본 원칙으로 둔다.

## 관련 결정

- 모든 사용자 역할, 캐릭터, 등장인물은 명확한 성인이라는 전제로 설계한다.
- 평행세계 분기 시 새 세계선은 **분기 지점 당시**의 호감도와 관계 상태를 복제한다.
- 분기 이후 각 세계선은 서로 독립적인 하트게이지, 관계 기억, 장면 상태를 가진다.
- 다른 세계선에서 발생한 호감도 변화나 사건은 자동으로 동기화하지 않는다.
- 장면 캡슐과 선톡은 모두 현재 구현 범위에서 보류한다.

## 제품 원칙

- 선톡은 단순 타이머가 아니라 현재 대화 상태를 통과한 경우에만 허용한다.
- 현실에서 시간이 지났다는 이유만으로 진행 중인 가상 장면의 시간을 자동 진행하지 않는다.
- 사용자가 떠난 사이 캐릭터가 사용자의 역할이나 행동을 대신 결정하지 않는다.
- 선톡을 위해 캐릭터의 말투, 관계, 성격을 과장하거나 왜곡하지 않는다.
- 대화 도중 확인창이나 경고를 반복해서 띄우지 않는다.
- 성인모드의 노골적인 대화문을 알림, 진단 로그, 분석 데이터에 불필요하게 노출하지 않는다.

## 세계선별 대화 상태 초안

각 세계선은 마지막 메시지와 별도로 다음 숨은 상태를 저장한다.

| 상태 | 의미 | 기본 선톡 정책 |
| --- | --- | --- |
| `ACTIVE_SCENE` | 행동이나 상황극이 이어지는 중 | 금지 |
| `PAUSED_SCENE` | 사용자가 잠시 자리를 비웠거나 답을 미룬 상태 | 금지 |
| `UNCERTAIN` | 장면 종료 여부를 신뢰성 있게 판정할 수 없음 | 금지 |
| `CLOSED_SCENE` | 장면이 자연스럽게 마무리되고 여운만 남음 | 조건부 허용 |
| `AMBIENT_CHAT` | 특별한 장면 없이 일상 대화가 멈춤 | 허용 후보 |
| `PROMISED_CONTACT` | 나중에 연락하기로 대화 안에서 명시함 | 약속 조건에 맞춰 허용 후보 |

시간 경과만으로 `ACTIVE_SCENE`, `PAUSED_SCENE`, `UNCERTAIN`을 `AMBIENT_CHAT`으로
자동 전환하지 않는다. 분기 시에는 분기 지점의 상태를 복제하고, 이후에는 세계선별로 독립 갱신한다.

## 상태 판정 초안

Gemini 3.7 Flash가 일반 응답을 생성할 때 사용자에게 보이지 않는 구조화 메타데이터를 함께
반환하는 방식을 우선 검토한다. 별도의 상태 판정 호출은 추가하지 않는다.

```json
{
  "sceneState": "ACTIVE_SCENE",
  "expectsUserContinuation": true,
  "proactiveMessageAllowed": false
}
```

메타데이터 스키마는 시스템 프롬프트의 안정 접두사에 고정해 명시적 캐싱을 불필요하게
흔들지 않아야 한다. 파싱 실패, 누락, 상충하는 값은 모두 `UNCERTAIN`으로 취급한다.

AI의 판정만으로 발송하지 않고 앱이 다음 조건을 다시 검사한다.

- 장면 상태가 `ACTIVE_SCENE`, `PAUSED_SCENE`, `UNCERTAIN`이 아닌가
- 캐릭터의 마지막 말이 사용자의 대답이나 행동을 기다리고 있지 않은가
- 사용자가 최근 새 메시지를 보냈거나 방을 다시 열지 않았는가
- 동일 캐릭터와 세계선에 이미 발송 후보가 존재하지 않는가
- 현재 선톡 대상 세계선이 여전히 활성 세계선인가
- 캐릭터 또는 채팅방의 선톡이 음소거되지 않았는가
- 조용한 시간대와 최소 간격을 통과했는가

## 예약과 발송

예약 시점에는 메시지 본문을 만들지 않고 발송 후보와 조건만 저장한다. 실제 시간이 되면
현재 상태를 다시 검사하고, 모든 조건을 통과한 경우에만 모델을 호출해 메시지를 생성한다.

```text
후보 등록
  -> 발송 직전 세계선과 대화 상태 재검사
  -> 새 사용자 메시지 또는 세계선 전환 시 취소
  -> 조건 통과 시에만 본문 생성
  -> 생성 후 상태가 다시 바뀌었다면 발송 취소
```

앱을 완전히 종료한 경우의 신뢰성을 위해 Android `WorkManager` 기반 로컬 예약과 서버 푸시
방식을 비교한다. 로컬 방식은 서버 구성과 개인정보 노출이 적지만 정확한 발송 시각을 보장하기
어렵다. 서버 방식은 신뢰성이 높지만 대화 상태 전달, 인증, 저장 범위, 운영 비용을 별도로
설계해야 한다. 구현 전에 두 방식의 실제 기기 동작과 비용을 측정해 결정한다.

## 선톡 종류

선톡 후보는 다음 유형으로 구분한다.

1. 일상적인 안부
2. 이전 대화에 대한 자연스러운 후속 연락
3. 대화 중 명시적으로 약속한 연락
4. 마무리된 장면의 감정이나 여운
5. 미완료 장면의 능동적 이어 말하기

5번은 기본 비활성화 후보로 둔다. 활성화 가능성을 재검토하더라도 캐릭터별 사용자 설정과
명시적인 장면 상태가 모두 있어야 하며, 사용자의 역할이나 행동을 대신 생성해서는 안 된다.

## 세계선 규칙

- 기본적으로 채팅방에서 마지막으로 활성화한 세계선 하나만 선톡 후보가 될 수 있다.
- 비활성 세계선과 삭제된 세계선의 예약은 취소한다.
- 여러 세계선의 동일 캐릭터가 동시에 선톡하지 않는다.
- 알림을 누르면 메시지가 생성된 정확한 방과 세계선으로 이동한다.
- 선톡 메시지도 해당 세계선의 정식 대화 기록과 `turnId` 흐름에 들어가는 방향을 우선 검토한다.
- 선톡이 미래 API 문맥에 포함되는 방식은 일반 메시지와 동일해야 하지만, 사용자 메시지가 없는
  AI 단독 턴을 기존 저장·압축 로직이 안전하게 처리하는지 먼저 검증한다.

## 빈도와 캐릭터성

- 캐릭터마다 선톡 성향과 최소 간격을 다르게 둘 수 있다.
- 호감도는 빈도 판단의 한 요소일 뿐, 높다고 무조건 자주 보내지는 않게 한다.
- 답장이 없을 때 연속 선톡하거나 응답을 재촉하지 않는다.
- 동시에 둘 이상의 발송 후보를 쌓지 않는다.
- 캐릭터의 원래 성격에서 자연스럽게 나올 수 있는 연락만 생성한다.

## 프라이버시 초안

- 잠금 화면 알림은 기본적으로 실제 메시지 본문을 숨기는 안을 우선 검토한다.
- 사용자가 캐릭터 이름, 일반 알림 문구, 실제 본문의 노출 수준을 선택할 수 있게 한다.
- 실제 대화 원문과 생성된 선톡 본문을 디버그 로그, 분석 이벤트, 오류 보고서에 기록하지 않는다.
- 서버 푸시를 채택할 경우 서버가 평문 대화 문맥을 보관하지 않는 구조를 먼저 검토한다.
- 예약 취소와 생성 실패는 민감한 본문 없이 상태 코드와 시각 정보만 기록한다.

## 구현 전 결정할 사항

- 미완료 장면을 시간이 지나도 영구 동결할지
- 장기간 방치 후 장면 밖의 중립적인 연락을 허용할지
- 사용자가 장면 종료나 일시정지를 직접 표시할 수 있게 할지
- `PROMISED_CONTACT`의 시간과 조건을 어떻게 추출하고 보존할지
- 선톡이 호감도에 영향을 주는지, 사용자의 답장이 있을 때만 영향을 주는지
- 여러 세계선 중 선톡 가능한 세계선을 사용자가 직접 지정할 수 있게 할지
- 로컬 예약과 서버 푸시 중 어느 전달 방식을 사용할지
- 실제 메시지 생성 시 현재 세계선 문맥을 어디까지 포함할지
- 캐릭터별 빈도 기본값과 조용한 시간대 기본값

## 구현 재개 시 검증 순서

1. 실제 대화 원문 없이 상태 전이 테스트 자료를 만든다.
2. 진행 중, 일시정지, 불확실 장면에서 후보가 생성되지 않는지 단위 테스트한다.
3. 후보 등록 후 사용자 메시지, 세계선 전환, 삭제, 음소거에 따라 취소되는지 검증한다.
4. AI 메타데이터 누락과 파싱 실패가 `UNCERTAIN`으로 닫히는지 검증한다.
5. 선톡을 일반 대화 기록과 압축 문맥에 넣어도 `turnId`와 `canonicalText`가 깨지지 않는지 확인한다.
6. Gemini 3.7 Flash의 안정 접두사와 명시적 캐시 적중에 미치는 영향을 측정한다.
7. 실제 Android 기기에서 앱 실행 중, 백그라운드, 강제 종료, 재부팅, 오프라인 흐름을 확인한다.
8. 잠금 화면과 앱 전환 화면에서 민감한 본문이 노출되지 않는지 확인한다.

## 재검토 완료 조건

다음 질문에 사용자가 명확히 답한 뒤에만 구현 계획으로 승격한다.

- 진행 중이거나 애매한 장면을 얼마나 오래 동결할 것인가
- 미완료 장면에서 캐릭터가 먼저 말을 이어갈 수 있는가
- 어떤 세계선이 선톡의 주체가 되는가
- 실제 알림에 어느 정도의 내용을 노출할 것인가
- 로컬 예약과 서버 푸시 중 어느 신뢰성·비용 수준을 선택할 것인가
