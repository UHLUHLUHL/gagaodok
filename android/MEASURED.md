# 안드로이드 카카오톡 실측표

사용자가 보낸 기기 캡처(1440×2936)를 화소 단위로 재서 정리한 표입니다.
**여기 적힌 숫자는 짐작이 아니라 잰 값입니다.** 짐작인 것은 그렇게 표시했습니다.

## 자의 기준

밀도를 먼저 확정했습니다. 우리 앱은 대화방 아바타를 `38.dp`로 선언하는데
같은 기기 캡처에서 143px로 나왔습니다. 143 ÷ 38 = 3.76이므로

- **밀도 3.75, 화면 폭 1440px = 384dp**

이 자로 아래 화소값을 dp로 옮겼습니다. 다른 기기에서 잰 값을 여기 섞지 마세요.

### 글꼴 배율은 따로 갈라내야 합니다

**길이는 밀도만 알면 되지만, 글자는 배율이 하나 더 끼어 있습니다.**

같은 글자('대박')를 재니 우리 것이 원조보다 8.5% 컸습니다. 글자 크기를 줄이려다
멈추고, 한 줄짜리 말풍선 높이로 배율을 갈라냈습니다. 같은 15sp인데
에뮬레이터(배율 1.0)에서 141px, 사용자 기기에서 134px입니다.
안쪽 여백 60px을 빼면 줄 상자가 81 대 74이므로 **사용자 기기 배율은 약 0.91**입니다.

그 배율을 걷어내면 원조 본문은 14.7sp라서 지금 쓰는 15sp가 맞습니다.
모르고 줄였으면 원조보다 작아졌을 자리입니다.

에뮬레이터로 대조할 때는 `adb shell settings put system font_scale 0.94`로
맞춰 두고 쟀습니다. 안 맞추면 모든 글자 관련 측정이 어긋납니다.

## 프로필 도형

아바타는 둥근 사각형이 아니라 **초타원(스퀘어클)**입니다.
채팅 목록의 180×180px 아바타에서 180개 행의 폭을 재어 맞췄습니다.

```
|x/a|^n + |y/a|^n = 1,  n = 2.70
```

잔차 0.0001. n=2로 두면(타원) 0.0203, n=4로 두면 0.0349이므로 2.70이 뚜렷하게 맞습니다.
예측과 실측이 모든 행에서 1px 안쪽으로 일치합니다(맨 위 한 줄만 앤티에일리어싱으로 6px 차이).

### 세로 정렬 — 우리가 틀렸던 자리

원조는 **아바타의 위 끝이 이름 줄의 위 끝과 같습니다.**

- 아바타 위 끝 1024 → 이름 잉크 위 끝 1043 (글꼴 여백 19px)
- 이름 잉크 아래 끝 1081 → 첫 말풍선 위 끝 1110

우리 앱은 이름 잉크가 583..619인데 아바타가 633에서 시작했습니다.
이름이 제 줄을 따로 차지하고 아바타가 그 아래로 밀린 것이라,
사용자가 "말풍선 위치가 어긋난다"고 한 자리가 여기입니다.

### 꼬리

묶음의 첫 말풍선에만 붙습니다. 반지름 49px 기준으로 잰 윤곽입니다.
몸통 왼쪽 위 모서리를 원점으로 삼았습니다.

- 평평한 윗변이 끝나는 곳 (49, 0)
- 아래로 파인 골 **(15, 15)**
- 뿔 끝 **(−7, 4.5)** — 몸통보다 7px 바깥
- 뿔 아랫면이 몸통 왼쪽 변에 붙는 곳 (0, 25)

뿔 자체는 작지만 **골이 깊어서** 깃발처럼 보입니다. 골 없이 볼록하게만 그리면
꼬리가 있어도 없는 것처럼 읽힙니다(우리 첫 판이 그랬습니다).

## 앱 아이콘

런처 타일 대비 말풍선 폭입니다.

| | 비율 |
|---|---|
| 원조 카카오톡 | 182/250 = 0.73 |
| 우리 맥 판 | 310/412 = 0.75 |
| 우리 안드로이드 판(고치기 전) | 158/165 = 0.96 |

맥 판이 원조와 거의 같아서 맥에서는 나란히 놓아도 같아 보였고,
안드로이드 판만 적응형 아이콘의 안전 영역을 넘겨 그려 커 보였습니다.
432px 캔버스에서 전경 잉크 폭을 268 → 210으로 줄이면 0.75가 됩니다.
210/432은 52.5dp로, 구글이 권하는 정사각 키라인 52dp와도 맞습니다.

고친 뒤 픽셀 런처에서 재니 163/226 = 0.721이 나왔습니다. 원 마스크라 타일이
스퀘어클보다 크게 잡혀서 그렇고, 사용자의 삼성 런처 기준으로 되짚으면 0.750입니다.

## 고친 뒤 대조표

에뮬레이터를 같은 자(1440×2936, 밀도 3.75, 글꼴 배율 0.94)로 맞추고 다시 잰 값입니다.

| 대화방 아바타 왼쪽 | 23 | 23 |
| 대화방 아바타 크기 | 143 | 143 |
| 받은 말풍선 왼쪽 | 188 | 189 |
| 내 말풍선 오른쪽 | 1413 | 1409 |
| 한 줄 말풍선 높이 | 130 | 133 |
| 같은 묶음 말풍선 간격 | 27 | 28 |
| 본문 잉크 높이 | 47 | 49 |
| 목록 아바타 | 180 @ x=60 | 180 @ x=60 |
| 친구 아바타 | 150 @ x=60 | 150 @ x=60 |
| 친구 행 간격 | 211 | 210 |
| 아바타 곡선 지수 | 2.70 | 2.74 |

아바타 지수 2.74는 곡선을 24토막 직선으로 근사한 탓이고, 원조를 잰 값 자체의
오차 범위 안입니다.

**일부러 따라 하지 않은 것이 하나 있습니다.** 원조는 묶음의 마지막 말풍선 앞
간격만 27이 아니라 34입니다. 두 묶음에서 똑같이 반복되므로 우연이 아니지만
왜 그런지 설명할 규칙을 못 찾았습니다. 근거 없이 숫자만 맞추면 나중에
말풍선 구조를 바꿀 때 이유를 몰라 그대로 두게 되므로, 27로 통일했습니다.

### 다시 겪지 않으려면

**1. Material3의 `IconButton`은 크기를 내가 정하는 자리에 쓰면 안 됩니다.**
넘겨받은 수정자 **뒤에** 자기 크기(40dp)와 최소 터치 넓이(48dp)를 붙입니다.
그래서 `.size(28.dp)`가 조용히 무시됩니다. 크기를 정해야 하면 `Box` + `clickable`로 짭니다.

**2. `.size()` 다음에 `.padding()`을 쓰면 여백이 안쪽을 파먹습니다.**
`.size(12.dp).padding(start = 3.dp)`는 12dp 상자 안에 9dp짜리 그림을 남깁니다.
간격을 주려면 `.padding(...).size(...)` 순서여야 합니다.

**3. 아이콘은 "상자 크기"가 아니라 "잉크 크기"로 견줍니다.**
Material 아이콘은 상자의 0.8쯤만 채우고, 우리가 직접 그린 아이콘은 꽉 채웁니다.
같은 dp를 줘도 나란히 놓으면 다르게 보입니다. 우리 아이콘은 잉크가 곧 지정 크기가
되도록 설계 상자를 잉크 상자에 맞춰 두었습니다(톱니바퀴가 그래서 어긋나 있었습니다).

**4. 애니메이션은 여백이 아니라 `offset`으로 움직입니다.**
여백은 자리를 차지해서 점이 뜰 때마다 옆 글자가 밀리고 가운데 정렬이 흐트러집니다.
